# Дедупликация и событийные кластеры

**Статус:** Draft 0.1

## 1. Уровни

Технический дубль определяется по source external ID, canonical URL/hash и нормализованному content hash. Смысловой дубль и новая стадия определяются отдельно по сущностям, времени, типу события, фактам и semantic similarity.

## 2. Решение

Candidate retrieval использует временное окно, сущности и embeddings; scorer возвращает `same_document`, `same_event_no_new_facts`, `new_stage`, `related_event`, `different` с evidence и confidence. Детерминированные признаки имеют приоритет над LLM-объяснением.

## 3. Правила

Автоматическое объединение — только выше утверждённого порога и без конфликтующих ключевых фактов. Пограничные случаи идут в review queue. Merge/split кластеров версионируется и обратим; исходные материалы не удаляются. Новая стадия создаёт новую package version либо новый пакет по редакционной policy.

## 4. Тесты

Повторная загрузка URL, syndication, перевод одной новости, слух→подтверждение, трейлер→премьера, перенос даты, одноимённые люди и события в разных странах. Метрики: precision auto-merge как основная, recall candidates, false merge, review rate и latency.

## 5. Приёмка

Каждое решение объяснимо сохранёнными признаками; ошибочное объединение можно отменить; ни один источник не теряется; пороги конфигурируются и проверяются eval-набором.
